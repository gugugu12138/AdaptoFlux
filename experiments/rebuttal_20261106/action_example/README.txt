共享特征－动作评分－互斥路由：原生 ATF 执行核验
日期：2026-11-06

结论
固定 seed 104 的飞鸟控制器通过显式适配器在未修改的
GraphProcessor.infer_with_graph 上执行。固定前 20 个测试回合、20,480 步，
与原 kernel.tick 函数体及独立 Python 解释器的特征、评分、动作、状态逐步一致；
最大绝对误差均为 0。前 2 回合共 2,048 步还与已有 final_raw.npz 冻结轨迹一致。
另有 49 个边界输入探针及 49 次打乱节点/边插入顺序的复核，全部通过。
正式运行用时 48.22 秒（该时长不是执行器性能基准）。

范围
这是冻结模型的执行语义迁移核验，不是重新训练、搜索改进、独立泛化估计，
也不证明无需适配即可兼容。20 个回合来自之前已用过的正式测试流，按编号连续
取首 20 个，没有依据成绩挑选。模型是先前验证选中的 seed 104，未重新选模。
该前缀中 20 个回合均成功，只作为轨迹一致性的结果记录。

适配方法
1. 原始感知读取、旧状态读取、所有算术特征、88 个冻结系数、逐项乘法、
   逐项求和、互斥路由和两个零输出动作 sink 均展开为真实原生节点。
2. 旧状态以不可变快照输入，所有特征和评分计算完成后，显式 state_commit
   节点汇总四个发射源并提交下一步状态；路由依赖它产生的 completion token。
   共享模式有四个储存槽位，但两两相同，只有两个独立动态通道。
3. 路由随机数 u 是所有执行器共用的显式外部输入，不受遍历顺序影响。
4. 动作 sink 的副作用是将动作身份写入 StepContext 的动作回执列表，输出数为 0。
   环境 advance 在整张图执行完成后统一推进，并非由每个 sink 直接修改物理环境。
5. 同步提交、路由和方法语义由适配器显式提供；没有修改核心，也没有把它解释为
   原核心自动推断副作用依赖、自动消除共享状态写冲突或保证并发安全。
6. 图的输入槽位/输出索引/元数据类型由适配器检查。该检查不是原 GraphProcessor
   自带的新增验证能力。这里仅核验串行执行。

节点与边计数
冻结导出图：314 节点、411 边。
原生适配图：316 节点、565 边。
节点差异：用 root 代替 observation（净 0），增加 collapse 和 state_commit（净 +2）。
边差异：
  88 条冻结常数的无作用触发边（原 GP 要求处理节点至少有一个前驱）；
   4 条显式旧状态读取边；
   8 条 state_commit 输入边（旧状态、StepContext、四发射、两评分屏障）；
   2 条路由额外输入边（同源随机数、提交完成 token）；
  52 条仅用于核验的 collapse 观察边（44 特征＋2 评分＋2 许可＋4 新状态）。
合计 +154 边。动作 sink 没有观察输出或其他出边。

参考来源的安全加载
reproduce.py 为 NumPy-only、带 __main__ 保护的独立解释器，仅只读加载。
kernel.py 使用 AST 提取原 tick 函数体并移除 JIT 装饰器执行；未改写函数体，
未导入 corrected/common.py 或任何 ATF-nodes 包。这样避免其导入时改写缓存路径。
本程序使用 Python -B、禁用 Numba JIT，所有新结果及缓存只在当前目录。
protocol_formal.json 和 results_formal.json 保留来源 SHA256；读入的来源和原生核心
在正式运行前后哈希一致。ATF-nodes 和原生核心均未修改。

边界核验
同一冻结结构的诊断配置：原配置、所有评分相等、10%探索与平局、关闭路由、
无状态、即时共享、私有记忆；每种 7 个固定 u，共 49 个探针。另将节点和边的
插入顺序随机重排，重复相同 49 个探针。修改的诊断配置不用于报告任务性能。
采用不相等的旧共享槽位，额外核对提交前平均与提交后两两相同的精确语义。
