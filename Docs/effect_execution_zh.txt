ATF 副作用顺序与并行执行：集成说明

零、开关用法与保存约定

默认开启，不改变此分支已有的默认行为。创建时明确关闭：
  model = AdaptoFlux(values=X, input_types_list=['scalar'],
                    enable_effect_ordering=False)
独立使用图处理器也支持同一参数：
  processor = GraphProcessor(graph, methods, enable_effect_ordering=False)

已有模型通过接口切换，不能直接写只读属性：
  model.set_effect_ordering(False)       # 关闭
  model.set_effect_ordering(True)        # 重新开启
  print(model.enable_effect_ordering)   # 查看当前选择
独立处理器同样有set_effect_ordering接口。开关只接受True/False。

开启：冻结副作用顺序，等待冲突状态访问完成；状态图逐个完成整个样本。
关闭：只等待数据前驱，不生成额外控制依赖，不约束旧的冻结顺序；恢复按
节点处理整批样本的方式（A1,A2,B1,B2），允许原有向量化及标量回退。
关闭不会把方法声明改成pure，也不会移除端口、DAG、签名、文件一致性校验
及实例锁；这是调度模式开关，不是把执行器代码整体退回历史版本。
因此关闭也不能理解为完全消除计划准备开销。压缩器仍遵守纯函数限制。

关闭后，具有共享状态且没有显式数据依赖的节点可能因线程完成顺序或图
拓扑顺序变化产生不同结果；文件重排也不再承诺恢复相同的隐式状态顺序。
重新开启时以当前数据图选择并冻结新顺序，必须重新评价任务表现；切换
不会重置环境，也不会自动重新训练或刷新已有评分。关闭时调用显式的
set_execution_order会报错，因为该模式不承诺执行这个额外顺序。

模型复制、内置训练和保存加载保持开关。加载以文件中保存的设置为准，
而不是接收实例的构造参数；不带开关字段的旧计划按开启解释，无计划的
旧模型沿用此前的保守迁移方式。图元数据与计划中的开关冲突会拒绝加载。
若需要更改一个已加载模型的模式，请在load_model之后调用切换接口。

新抽取的复合方法继承来源模型的模式，并作为其内部执行契约保存。已有
复合方法可能被多个模型共享，切换外层模型不会递归改写这些方法的模式；
若要求所有内部图都关闭，应从关闭模式的模型重新抽取相应复合方法。
以下关于冻结顺序、状态逐样本和跨调度一致性的说明均以开启模式为前提。

一、解决的问题

类型兼容和DAG无环，只能约束数据传递，不能自动决定共享状态的访问顺序。
初态s=1，先执行s+=1再执行s*=2得到4；反过来得到3。这两个节点即使没有
数据依赖，也必须把选定的先后关系作为程序语义保存下来。

本实现保留隐式状态：原函数仍然可以读写环境对象。另存一份执行计划，记录
稳定节点身份、语义顺序和效果声明。控制依赖仅供调度器等待完成，不变成
函数的数据参数，也不要求零输出动作伪造一个数值输出。

二、如何声明方法

无副作用的数值方法：
  @method_profile(input_types=['scalar'], output_types=['scalar'], pure=True)
  def square(x):
      return x*x

读取环境：
  @method_profile(input_types=['scalar'], output_types=['scalar'], reads={'env'})
  def read_position(dummy):
      return STATE.pos

读写环境：
  @method_profile(input_types=['scalar'], output_types=['scalar'],
                  reads={'env'}, writes={'env'})
  def move(delta):
      STATE.pos += delta
      return STATE.pos

旧方法未声明效果时默认为unknown，不因为数值类型或group名称而认作纯函数。
unknown与所有非纯访问保守排序。显式writes={'*'}表示写入任意资源；
reads={'*'}表示读取任意资源。没有冲突的只读操作及独立资源仍可并行。

声明是一项调用契约，不是自动证明。pure也不能修改共享输入数组/对象。
资源名使用精确字符串匹配，不推断别名、对象身份或父子路径：env和env.pos
是两个不同标签。如果实际访问同一对象，应使用同一个资源名，或保守用'*'。
随机数流、文件、数据库和回调所访问的外部对象也属于要声明的资源。

三、建图、训练和运行各负责什么

1. 初次准备：graph_processor.prepare_execution_plan()选择一个与数据依赖
   相容的顺序，并赋予内部节点稳定的_atf_uid。首次顺序沿用当前图的拓扑
   顺序；因此未冻结的两个独立构图过程，仍可能定义不同的有状态程序。
2. 图生长或方法替换：保存已有节点的相对语义顺序，新节点按数据约束插入。
   与已有顺序冲突的修改被拒绝；不能在运行时悄悄换一种顺序使它可执行。
3. 如果训练要搜索另一种顺序，显式调用set_execution_order(内部节点列表)，
   然后把它当作新候选重新评价。接口不自动替训练器搜索排列。
4. GraphEvo在副本上构造并评价候选，接受时整体采用该图与计划，避免接受时
   再删建节点而改变语义。自定义损失/准确率回调前也会准备计划。
5. LayerGrow的添加/回退、节点替换、子图替换均会在修改后验证；失败时恢复
   原图对象及层信息，不给PathGenerator留下悬空或半完成的图。
6. 运行时按“数据前驱与控制前驱都完成”放行节点。每次调用重新建立就绪
   计数，完成信号不跨调用保存。串行与线程执行共用参数绑定和结果聚合逻辑。

四、批量、线程和错误语义

纯函数批量保持原有向量化通路。存在状态访问时，按完整样本逐个执行：
先完成样本1的全部节点，再运行样本2。不会把它交错成A1,A2,B1,B2。
样本之间不会自动重置外部状态；需要独立环境时由用户创建或重置环境。

同一个GraphProcessor实例的推理调用使用实例锁串行进入；内部无冲突节点
仍能使用线程池。不同实例若共享同一全局环境，仍需要调用方隔离或同步。
不支持在执行期间并发修改graph、方法池、效果声明或输入对象。

根输入宽度、端口和计划在用户函数执行前检查。工作线程失败时不再放行
依赖它的后继，也不会陷入等待永远不就绪节点的循环。已发生的用户副作用
不会自动回滚，因此函数本身的运行时异常不等于环境事务回滚。
一致性保证针对成功执行；失败时，某个独立分支在并行模式中可能已执行，
而串行模式还没执行到它，不能承诺失败调用的外部状态也逐步相同。

五、保存和加载

AdaptoFlux.save_model保存graph.json及execution_plan.json，JSON图内也包含
完整计划。GEXF用于可视化和兼容读取，但新模型从GEXF加载时必须带计划侧车。
加载先验证稳定身份、顺序、数据端口、方法签名及逐节点效果声明，全部通过
才替换当前模型，并同步PathGenerator的图引用。损坏或矛盾的计划会报错，
不会静默回退到另一种执行顺序。旧模型无计划且无稳定UID时可首次保守冻结。

旧图没有input_slot时，会把原来的入边绑定顺序显式固定，避免存储重排改变
减法等非交换算子的参数。collapse的数据坐标要求唯一，以固定聚合顺序。

本功能保存执行顺序与声明，不序列化Python闭包、外部环境或聚合配置，也
不认证函数源码是否相同。复现需使用同一方法实现、聚合器、初态、输入和
随机性设置。可把随机数作为输入，或把共享随机流作为资源声明并固定顺序。

六、复合方法和兼容性

抽取的复合方法保守合并内部读写集合，任一内部方法unknown则整体unknown。
跨越外部状态访问的非连续片段不会被压成一次原子方法调用，否则会改变
原程序的交错语义。旧提取器尚不能表达零输出动作边界，因此暂不抽取这些
动作sink；运行器本身可以执行它们。

没有副作用等价证明的符号/数值压缩只对明确声明纯的程序启用。旧方法池
如果全部未声明，仍能运行，但并行度及允许的压缩范围会保守下降。

旧版本的状态批量按节点交错执行，新版本采用完整样本顺序；这是明确的
语义修正。对外部状态有依赖的旧批量程序需要检查，不能承诺结果保持旧交错。

      Test/test_effect_toggle_persistence.py -q -p no:cacheprovider
上面的pytest命令请合并为一行。

测试覆盖非交换状态写入、读写顺序、全部合法调度的小图核验、资源通配、
独立分支实际并行、文件/节点/边重排、失败传播、零输出动作、批量语义、
训练接受/回退、生长、复合方法和保存加载拒绝不一致计划。

八、当前实现成本与保证范围

为兼容用户直接编辑NetworkX图，推理前会重新验证/构建计划，尚未用缓存
优化这一步。不能把修改前论文中的性能数字直接归给这个新执行器。
保证针对正确声明下的数值输出、动作及状态结果，不要求线程完成顺序、
诊断日志排序或耗时相同，也不是任意黑盒副作用的自动安全证明。
